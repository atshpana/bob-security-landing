# تقرير تصحيح الفرع استنادًا إلى ملف BOB 4.0 المرفوع

## نتيجة المراجعة
النسخة القديمة من الفرع أنشأت خادم Node.js ومخطط PostgreSQL ومعاينة ويب داخل نفس الصفحة. هذا لا يطابق §3 و§22.1 من المرجع، لأن التقنية الحاكمة هي: Flutter/Kotlin للموبايل، React للويب، FastAPI للخلفية، MySQL/Redis للبيانات.

## التصحيحات المرفوعة
1. تثبيت خريطة إصدار المنتج الواحد: Foundation → Public → Personal → Managed.
2. تثبيت 104 شاشة أم، 35 تدفق فرعي، 40 قدرة تحت بوابات إنتاج مغلقة، وتصحيح أسماء M-22/S-03/W-08 من جدول §21.44.1.
3. إنشاء مصدر ويب React مستقل مع موقع عام وأدوار ولوحات ومعاينة هاتف وعقود شاشات، باستخدام رمز الألوان الحاكمة في §21.3.
4. إنشاء تطبيق Flutter + Kotlin بهوية واحدة ومسارات M-10/M-13/M-21/M-22/M-23، ولا يتم تضمين أذونات حساسة في Manifest.
5. إنشاء FastAPI بعقد مستخدم/مؤسسة يعزل البيانات ويفشل مغلقًا، مع منع دعوات الأسرة قبل CFG-AGE-002.
6. إزالة مخطط PostgreSQL واستبداله بمسودة MySQL؛ Redis ودفع Play وAMAPI وFCM غير مهيئين.
7. إضافة اختبارات معمارية وآلية؛ نجاحها ليس بديلًا عن الجهاز الحقيقي/التحقق القانوني/بوابات النشر.

## أقسام حاكمة
§§0.8، 0.8.1، 2.1–2.4، 3–7، 9–10، 15–16، 21.3، 21.22–21.44.1، 22.1، 22.11، 23، 29.2.1، 29.3، 29.7–29.9.

## التسليم والحدود
هذا **مشروع بناء جزئي متعدد الطبقات** وليس المنتج النهائي. واجهات React والموبايل هي مسارات مُنفّذة جزئيًا ومعاينات تجريبية. عند مرحلة قاعدة البيانات يتم اعتماد المخطط/العزل/الاحتفاظ/الهجرة والتوثيق، ثم توصيل MySQL وRedis، وبعدها تكامل الأجهزة الحقيقي والتأهيل والبوابات. لا تُدمج هذه التغييرات في `main` دون مراجعة واعتماد.
